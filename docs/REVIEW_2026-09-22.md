# Independent implementation review

Review date 2026-09-22.

Scope reviewed

- public API
- conversation planner
- policy composition
- prompt construction
- context budgets
- voice handling
- validators
- provider abstraction
- configuration
- multilingual behavior
- tests
- CI
- documentation and stated architecture

## Review outcome

No release-blocking architectural issue remains for the current 0.1 scope after the fixes listed below.

The framework is still an early communication core. It is suitable for controlled integration into a first consumer such as Profi Worker, but it should not yet be described as fully production-proven across every channel and language.

## Findings fixed in this review

### High. Conversation history could inject a system role

Previous behavior

A Message with role system from caller-supplied history was preserved as a provider system message.

Risk

If upstream data maps an untrusted platform message to the wrong role, that text receives stronger instruction priority than ordinary user data.

Fix

Conversation history is now normalized to only user and assistant. System-priority text can only be created by the framework.

Regression test

test_conversation_cannot_inject_system_role

### High. Trust boundaries were not explicit enough in the generated prompt

Previous behavior

Known context and voice examples were inserted into system content without a strong statement that embedded instructions were data.

Risk

Vacancy text, marketplace request text or a real writing sample can contain adversarial instructions.

Fix

The base policy now declares conversation, context values and voice examples untrusted. Context and examples are placed inside named data boundaries. The model is told not to follow role-changing or policy-changing instructions inside those regions.

Regression test

test_prompt_contains_untrusted_data_boundary

### High. One huge latest message could bypass the documented history budget

Previous behavior

The total-history loop allowed the first kept message even when it alone exceeded the intended budget.

Risk

Large scraped content could significantly expand prompts and cost, or crowd out policy.

Fix

Every individual message is clipped first. The final accumulated history also has a hard character ceiling.

Regression test

test_history_budget_applies_to_single_huge_latest_message

### Medium. Multilingual planner behavior was weaker than the product claim

Previous behavior

Question detection handled ASCII question punctuation, while scheduling, objection and agreement heuristics were mainly Russian and English.

Risk

Chinese chat could be classified as a disclosure even when it was a direct question. Spanish and Chinese common scheduling or objection turns could miss the intended action.

Fix

The planner now handles fullwidth Chinese question punctuation and common Chinese question endings. Basic Spanish and Chinese scheduling, objection and agreement patterns were added. The architecture still allows explicit message types and future language-specific classifiers.

Regression tests

- test_chinese_fullwidth_question_is_detected
- test_spanish_scheduling_is_detected
- test_chinese_objection_is_detected

### Medium. Voice examples were documented as selected but implementation used the first examples

Previous behavior

The prompt always took the first N voice examples.

Risk

Large voice libraries would not adapt to the current conversational situation.

Fix

A small deterministic lexical-overlap selector now prioritizes examples that share meaningful tokens with the latest incoming text, then fills remaining slots in stable order.

Regression test

test_voice_examples_are_selected_by_relevance_when_possible

### Medium. Empty model output was not explicitly validated

Previous behavior

A provider or mock could return whitespace and the normalized empty string had no dedicated hard issue.

Fix

empty_message is now a hard validation failure and participates in the existing repair path.

Regression test

test_empty_output_is_hard_issue

### Medium. LiteLLM options could collide with framework-owned call fields

Previous behavior

Caller options could contain keys such as messages or temperature, causing duplicate keyword arguments or bypassing intended ownership.

Fix

LiteLLMProvider rejects reserved option names at construction time.

Regression test

test_litellm_reserved_fields_cannot_be_overridden

### Medium. Configuration parsing trusted malformed provider option shapes

Previous behavior

A non-table TOML value could reach dict conversion and fail with a less useful exception.

Fix

Provider and provider options are validated as tables. Provider model is validated as a string.

Regression tests

tests/test_config.py

### Low. Repetit naming was inconsistent

Previous behavior

The initial preset used repetitor while the intended marketplace naming in project discussions is Repetit.

Fix

repetit is now the canonical added preset and repetitor remains as a compatibility alias.

### Low. Fullwidth question marks were not included in validator question counts

Fix

Both ASCII and fullwidth question marks participate in question constraints.

## Findings reviewed and accepted for 0.1

### Planner remains heuristic

The deterministic planner intentionally handles obvious conversational states first.

It does not yet provide a model-backed ambiguity fallback.

This is acceptable for 0.1 because explicit outer message types already exist, deterministic behavior is easy to test and the first consumer will provide real regression data.

A model-backed planner should only be added after ambiguous examples are collected.

### No semantic fact verifier yet

The prompt instructs the model to use only supplied facts, but validators do not yet prove factual consistency.

This is a known gap.

The recommended next layer is a post-generation factual consistency evaluator using structured profile facts and, where useful, a small LLM judge. This should be tested against false positives before becoming a blocking gate.

### No HTTP service yet

The Python library is sufficient for current Python consumers.

A language-neutral HTTP wrapper is a planned integration surface for Java, JavaScript, Go and other callers. It should mirror the stable request and result contracts rather than introduce new policy logic.

### No production observability adapter yet

Result metadata contains plan, issues, provider and prompt version, which is enough to instrument callers.

A native Langfuse hook can be added later when at least one production consumer exists.

### No live provider tests in CI

CI does not call paid cloud models or authenticated Codex and Claude installations.

This is intentional. Unit and integration tests stay deterministic and credential-free.

A separate opt-in provider smoke suite can be added for release validation.

### Evaluation dataset is still small

Current fixtures protect key known failures, but they are not enough to optimize prompts statistically.

The next major quality task is to collect anonymized real tutoring and job-search conversations and encode property-based expectations.

## Recommendation after review

Use Profi Worker as the first integration consumer.

Adopt prepare mode first if minimizing migration risk is important. Preserve existing model credentials and transport while framework planner, prompt and validation behavior is compared against current output.

Once the real conversation benchmark is large enough, switch that consumer to generate mode and remove duplicated local communication prompts.

Do not expand the core with a general agent runtime before this integration data exists.
